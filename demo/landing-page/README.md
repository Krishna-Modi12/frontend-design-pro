# Tracepoint — landing page

A dark-mode landing page for a fictional durable-execution product, generated by routing
`landing-pages` + `core/design-tokens.md`. It is a real, standalone Next.js 15 (App Router) +
React 19 + Tailwind v4 project with its own `package.json` and a dev server that boots.

`demo/showcase/` is the other runnable project under `demo/`; `dashboard/` and `auth-form/`
remain stub-typed reference files, compiled only against the ambient `declare module` stubs in
`demo/_stubs.d.ts`.

## Running it

```bash
cd demo/landing-page
npm install
npm run dev
```

Then open `http://localhost:3000`. The metric strip should read **48.2M / 310ms / 0**. If it
says *"Status feed unreachable"* the API route below is not answering — that is the page's
error state working correctly, not a styling bug.

Type-check with:

```bash
npm run typecheck
```

This runs against **real** vendor typings rather than `demo/_stubs.d.ts`, which is the stricter
of the two checks. `demo/tsconfig.json` excludes this directory for that reason.

The anti-slop constraint suites still cover it, and still must pass:

```bash
bash demo/validate.sh landing-page    # 17 AST + 39 regex constraints
```

## Where the data comes from

`app/page.tsx` fetches `/api/site/overview` on mount for its metric strip, price book,
testimonial verifications and region status. That endpoint belongs to the product the page
advertises; this repo ships the frontend only, so `app/api/site/overview/route.ts` serves
[`screenshot-fixture.json`](screenshot-fixture.json) in its place — imported, never restated, so
the screenshot and the data behind it cannot drift.

This is why `next.config.ts` does **not** set `output: "export"`: a static export drops route
handlers, the fetch would 404, and the page would render its error state.

## What's in here

- `app/page.tsx` — the shell: skip link, sticky header, the four sections, and the single
  `fetch` all of them share. One request because they share one failure mode.
- `app/layout.tsx`, `app/globals.css` — App Router entry, Geist + Geist Mono via
  `next/font/google`, and the mapping that points `tokens.css`'s font tokens at them.
- `tokens.css` — the `@theme` block. Must be compiled, not injected at runtime; a browser
  handed `@theme` in a `<style>` tag drops it as an unknown at-rule and every utility built
  from it resolves to nothing.
- `lib/tokens.ts` — the runtime half: plain CSS the page injects, plus the shared shells
  (`sectionShell`, `tapTarget`, `focusRing`, `cardShell`). It reads values back as
  `var(--color-*)` rather than restating them.
- `components/Hero.tsx` — asymmetric split, `forwardRef` CTA (the quickstart disclosure returns
  focus to it), workflow source in a keyboard-reachable `<pre>`, tabular-nums metric strip with
  loading, error and empty branches.
- `components/Features.tsx`, `Pricing.tsx` (monthly/annual toggle, `tabular-nums`),
  `Testimonials.tsx`, `Footer.tsx`.

## Screenshot

`screenshot.png` — 1920×1080, above the fold, dark scheme, reduced motion off, captured from
headless Chromium driving a production build of this app. `screenshot-full.png` is the whole
page at 1440 wide. Both are linked from the root [`README.md`](../../README.md).

Regenerate them after any change here:

```bash
npm run screenshots -- landing-page     # from the repo root
```

**A stale screenshot is a worse failure than a missing one** — a missing image is an honest gap,
a stale one misrepresents the page to everybody who never runs it. The capture spec is in
[`.github/SCREENSHOT_CONTRIBUTION.md`](../../.github/SCREENSHOT_CONTRIBUTION.md).

## The prompt that would generate this

> Build a dark-mode landing page for a developer tool that does durable execution — workflows
> that checkpoint each step to an append-only log so a worker that dies mid-run resumes where it
> stopped. Near-black surface built from real OKLCH tokens at a single hue, no raw hex anywhere
> in component code, one accent used only on primary actions and live status. Geist for display
> and Geist Mono for anything that has to align in a column — no Inter, Roboto, Poppins, DM Sans
> or Space Grotesk. No purple-to-pink-to-blue gradients, no equal-height card grids, no
> `min-h-screen` (use `min-h-[100dvh]`), no placeholder copy and no suspiciously round numbers.
>
> Sections: an asymmetric hero with a real code sample beside it and a live metric strip below;
> a capabilities section; three-tier pricing with a working monthly/annual toggle and
> `tabular-nums` prices; testimonials; a footer with region status. The metrics, price book,
> testimonial verifications and region status all come from one `GET /api/site/overview` call
> made on mount — one request, because if the control plane is down then showing live pricing
> next to a broken metric strip is worse than showing both as unavailable.
>
> Hold it to `core/accessibility-baseline.md` and `core/validate-checklist.md`: a skip link,
> 44px touch targets, a visible focus ring on every control, `aria-live` on the region that
> updates, `role="alert"` on the failure branch, exported `*Props` interfaces that are actually
> used as types, `forwardRef` where a ref is load-bearing, all four states with no `setTimeout`
> fake loader, `text-wrap: balance` on headings, and `…` rather than `...` in copy.
