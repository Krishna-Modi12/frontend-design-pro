Section 01 — Security

Two findings an agent would have shipped

Both live in reference files: the material an agent opens for depth and copies from most directly.

  • Stored XSS in the JSON-LD recipe

    JSON.stringify escapes quotes and backslashes. It does not escape <. Every schema on the page is built from CMS fields — a title, a product description, an FAQ answer — so one value carrying a closing script tag ends the element and executes. It renders in the root layout, on every page.

    skills/platform/references/seo.md
    FIXED escape at serialisation

  • No trust boundary on fetched content

    The research skill instructs an agent to browse arbitrary URLs and feed what it finds into a build pipeline — with nothing anywhere saying that fetched bytes are untrusted. It is the one skill that widens the trust boundary, and it had no rule about it.

    skills/design-research/SKILL.md
    FIXED now rule #1 in that skill
Section 02 — Enforcement

Three rules stated everywhere, checked nowhere

Each appears in the anti-slop wall, in the validation checklist, and in every host adapter. None of them had a constraint. The anti-example files had already begun annotating ❌ [RES] min-h-screen — citing an ID the suite did not define.

  • min-h-screen

    Named in four documents. 100vh ignores the mobile toolbar; the rule is min-h-[100dvh].

    was: nothingnow: RES-03

  • React.FC

    Banned by the wall since the pack existed. Erases children typing and blocks generic components.

    was: nothingnow: TS-02

  • onPress on web

    Scoped by import rather than filename — a React Native gold legitimately uses onPress, and a rule that failed it would be wrong rather than strict.

    was: nothingnow: PLAT-01
Section 03 — The blind spot

98% of the pack was outside every gate

The constraint runner globs code extensions. A reference is markdown. So the 55 example files were checked and the 117 references — roughly 418,453 tokens, and the part an agent actually opens — were not read by anything.

Shipped, under a heading reading “Must have”

<div class="min-h-screen bg-gradient-to-br
  from-violet-500 via-purple-500 to-pink-500">

What the same pack's wall bans, by name

min-h-screen → use min-h-[100dvh]
purple → pink → blue gradients

An agent routed to that file held both texts in one context window and had to pick a side. Gate 10 now runs the 16 ban-shaped constraints over every fenced code block in all 117 references, 19 skill routers and 8 core files. Presence checks are excluded on purpose: a nine-line snippet that omits a font declaration is correct, not defective, and a noisy gate gets muted.

Section 05 — Installer

The list that disagreed with what shipped

Auto-installable adapters were a hardcoded array in two setup scripts, while the adapter list itself was derived from the directory. Any adapter added without editing that array silently became “manual” — a working payload that never got written.

  • The fact now lives with the adapter

    An adapter declares itself manual by shipping a .manual file saying why. Auto means: no such file, and at least one payload to copy. Adding a directory is now the whole of adding an adapter, and the two scripts cannot drift apart from it.

    5 → 10 auto

Every figure on this page comes from a green python scripts/build_release.py --dry-run on the audited tree. Verify it by cloning and running npm run gates — the chain builds nothing and takes about eighty seconds.
