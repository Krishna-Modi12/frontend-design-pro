# Capability matrix

What this pack actually covers, layer by layer, against a target architecture spanning creative direction through evaluation. Every "present" row cites a real file or constraint ID that exists today; every "absent" row was confirmed absent by direct search, not assumed. Where a row says "prose only," that means the guidance exists in a skill or reference but nothing machine-checks it — a real gap, not a rounding error.

**How to read enforcement type:**

| Type | Means |
|---|---|
| `AST` | Checked by `scripts/parser_constraints.js` via the TypeScript compiler API |
| `regex` | Checked by `scripts/test_constraints.py`'s `CONSTRAINTS` list |
| `browser` | Checked by Playwright + axe-core in `tools/screenshots/`, currently **outside** the blocking gate chain |
| `prose` | Documented in a skill/core file, not machine-checked |
| `absent` | Confirmed absent by search — no rule, tool, doc, or demo covers it |

**Priority:** P0 = foundational gap · P1 = high-impact · P2 = useful enhancement · P3 = experimental / logged for later.

This file is regenerated by hand today (there is no figure-gate coverage for a capability matrix — see the Gate 11 note at the bottom). Treat the counts it cites (skills, constraints, gates) as a snapshot tied to whatever `metadata.json` said at audit time; re-derive them from a green `npm run gates` before trusting them in a future session, per this project's own standing rule.

## Deferred, explicitly (not silently)

These are real gaps this matrix identifies but that this pass does not attempt to close at full production rigor, because each is independently a multi-week effort and a shallow version would produce exactly the "files compile but nothing's actually verified" outcome this project's own culture (`docs/MAINTENANCE.md`, `CLAUDE.md`) explicitly warns against:

- Remaining 6 golden-project benchmark apps (Layer L)
- Objective scoring model / weighted rubric (Layer L)
- Skill/rule generator tooling, benchmark dashboards (Layer L)
- Screenshot → code / design-system inference (Layer D)
- Full Core Web Vitals field measurement (Layer G) — static/heuristic budgets are tractable now; real CWV data requires infrastructure this repo doesn't have (no deployed staging environment with RUM)
- Product-specific creative-direction system across 14 industries (Layer A, touched only glancingly via `brand_archetypes: 9` / `tone_directions: 14` in existing reference data)

## Note on this file's own figure-gate coverage

Every other count this project publishes (skills, constraints, gates, token depth) is recomputed from the filesystem by `scripts/check_figures.py` (Gate 11) — hand-editing one is a defect by this project's own standard. This file does not yet have that coverage: its "present/absent" judgments were derived by direct audit (three parallel codebase searches) rather than by a script, and its priority labels are a judgment call, not a computed value. That is a known limitation of the matrix itself, not swept under anything — a future pass could add a lightweight checker that at least verifies every "present" row's cited file/ID still exists, without attempting to automate the priority judgment.
