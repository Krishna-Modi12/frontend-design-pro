# Capability matrix

What this pack actually covers, layer by layer, against a target architecture spanning creative direction through evaluation. Every "present" row cites a real file or constraint ID that exists today; every "absent" row was confirmed absent by direct search, not assumed. Where a row says "prose only," that means the guidance exists in a skill or reference but nothing machine-checks it — a real gap, not a rounding error.

**How to read enforcement type:**

| Type | Means |
|---|---|
| `AST` | Checked by `scripts/parser_constraints.js` via the TypeScript compiler API |
| `regex` | Checked by `scripts/test_constraints.py`'s `CONSTRAINTS` list |
| `browser` | Checked by Playwright + axe-core in `tools/screenshots/`. Outside the 11 numbered gates — those run against a source tree, these need built apps and a browser — but **not** outside CI: `home-renderer`, `demo-renderer` and `visual-regression` all block a merge. The exception is `live-audit.mjs`, which is agent-driven and runs nowhere automatically. |
| `prose` | Documented in a skill/core file, not machine-checked |
| `absent` | Confirmed absent by search — no rule, tool, doc, or demo covers it |

**Priority:** P0 = foundational gap · P1 = high-impact · P2 = useful enhancement · P3 = experimental / logged for later.

This file is regenerated by hand today (there is no figure-gate coverage for a capability matrix — see the Gate 11 note at the bottom). Treat the counts it cites (skills, constraints, gates) as a snapshot tied to whatever `metadata.json` said at audit time; re-derive them from a green `npm run gates` before trusting them in a future session, per this project's own standing rule.

## Note on this file's own figure-gate coverage

Every other count this project publishes (skills, constraints, gates, token depth) is recomputed from the filesystem by `scripts/check_figures.py` (Gate 11) — hand-editing one is a defect by this project's own standard. This file does not yet have that coverage: its "present/absent" judgments were derived by direct audit (three parallel codebase searches) rather than by a script, and its priority labels are a judgment call, not a computed value. That is a known limitation of the matrix itself, not swept under anything.

Half of the fix that paragraph proposed has since arrived from elsewhere: `prose_paths()` (Gate 11, Stage 3) walks every `*.md` in the repository, this file included, and fails the build on any backticked path citation that does not resolve. So every **file** this matrix cites is checked. What is still unchecked is the other half — the constraint **IDs** (`A11Y-04`, `SLOP-05`) — and that gap is not an oversight either: the rows below deliberately cite IDs that do *not* exist, `SEC-01` among them, to record what was attempted and dropped. A checker asserting every cited ID resolves would fail on exactly the honesty this file exists to preserve, and telling the two cases apart is the judgment call the paragraph above already declines to automate.
